# 复核诊断分级设计

## 目标

复核区不再显示缺少事实依据的笼统结论。每条诊断必须说明检测对象、实际结果和影响；只有可能导致题目内容错误的问题使用红色。

## 数据

V2 结构化结果保留辅助 OCR 的原始文本。API 在原有 `review_reasons` 基础上生成 `review_diagnostics`，每项包含：

- `severity`：`critical`、`warning` 或 `info`
- `title`：简短、明确的结论
- `detail`：实际检测结果及其影响

辅助 OCR 未能提取完整题干时，诊断需引用其真实输出片段，并明确主 OCR 是否已经获得完整题干。

## 显示规则

- 红色 `critical`：数字或比例冲突、主题干缺失、配图结构不可靠等可能改变题意的问题。
- 橙色 `warning`：尚无人工真值等会阻止自动通过、但不表示内容已错误的流程项。
- 灰色 `info`：辅助 OCR 失败等不影响当前重建结果的补充信息。

前端优先渲染 `review_diagnostics`；旧数据缺少该字段时由 API 根据原因生成兼容诊断。

## 验证

- 单元测试验证辅助 OCR 原文被保存。
- API 测试验证三种严重程度及具体说明。
- 前端确认诊断按红、橙、灰三种样式显示。
